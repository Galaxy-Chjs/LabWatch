fix(ci): the backend job linted a directory that no longer exists

The first CI run on GitHub failed at "Lint" in the Backend job, which made the
wheel and E2E jobs skip. The cause was not a lint rule: the step ran
`ruff check labwatch backend`, and `backend/` was deleted when the code moved into
the `labwatch/` package. Ruff reported E902 "file not found" for the missing path
and exited non-zero, so a red build had nothing behind it but a stale path.

Fixed to `ruff check labwatch tests`, matching what the local runs used.

Why it was not caught locally: I was running `ruff check labwatch tests`, so the
stale argument only existed in the workflow. Two earlier attempts to find the
cause by reasoning about ruff versions were wrong; the actual evidence came from
reproducing the failure locally, where ruff printed exactly the same E902 the
runner did.

To stop this class of mistake, add scripts/check-workflow-paths.py: it parses
every `run:` step, extracts the arguments that look like repository paths, and
fails if one does not exist. It has been verified in both directions - it reports
zero problems now, and reports `backend does not exist` when the old argument is
put back. It runs as its own CI step.
